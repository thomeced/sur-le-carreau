## Story 0.1 — Tests de fumée et de régie (Playwright)
En tant que développeur, je veux un test automatique qui joue une partie de bout en bout afin de vérifier que rien ne casse à chaque story, à commencer par le découpage d'`index.html`.

### Critères d'acceptation
1. Étant donné le dépôt servi en local (`python3 -m http.server`), quand on lance `node tests/fumee.js`, alors le test ouvre `index.html?mode=serieux` en 1440×900, clique « Configurer sur cet écran », choisit une grille 2×2, lance la partie et joue tous les duels (en cliquant « Bonne réponse » ou en laissant tomber les chronos) jusqu'à l'écran du vainqueur.
2. Étant donné la même partie, quand une erreur JavaScript ou un `console.error` apparaît, alors le test échoue en affichant le message.
3. Étant donné deux onglets du même navigateur, quand on lance `node tests/regie.js`, alors l'écran du jeu est ouvert sur `index.html?mode=serieux`, la régie sur `index.html#arbitre=CODE` (code lu dans `#hcode`), la régie configure une partie en duel simple, la lance, envoie « Bonne réponse » puis « Passé », et l'écran du jeu en tient compte (score et chrono).
4. Étant donné les deux tests, quand on les lance sur la branche `main` actuelle, alors ils passent (référence avant le découpage).
5. Les tests se lancent avec une seule commande documentée en tête de chaque fichier, sans `npm install` dans le dépôt (Playwright est pris dans l'environnement de Claude).

### Tâches techniques
- [ ] `tests/serveur.js` : petit utilitaire commun (démarre `http.server` sur un port libre, ouvre Chrome via Playwright, collecte les erreurs de console, arrête tout).
- [ ] `tests/fumee.js` : critères 1 et 2 ; accélérer les duels en réglant `DUEL_SEC` via `page.evaluate` si nécessaire (sans toucher au code du jeu).
- [ ] `tests/regie.js` : critère 3, liaison `BroadcastChannel`.
- [ ] `tests/README.md` : comment lancer, ce que couvre chaque test.
- [ ] Vérifier le critère 4 sur `main`.

### Contexte dev
- Aucun changement du code du jeu dans cette story.
- Sélecteurs utiles : `#hcode` (code de l'accueil), `#setup`, `#arb`, boutons d'arbitrage dans `#arb`. Voir `CLAUDE.md`, section « Conventions » (tests automatisés).
- Le choix Funky ou Sérieux est sauté par `?mode=serieux`.
- Piège : la régie ne s'ouvre en mode partie qu'après un `hi` reçu ; attendre « relié ✓ ».
