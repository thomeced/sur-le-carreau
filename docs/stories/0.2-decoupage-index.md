## Story 0.2 — Découpage d'`index.html` en fichiers
En tant que développeur, je veux que le CSS et le JavaScript d'`index.html` soient répartis en fichiers par section afin que chaque chantier suivant touche un fichier court et lisible.

### Critères d'acceptation
1. Étant donné le découpage, quand on ouvre `index.html`, alors il ne contient plus que le balisage et les balises `<link>` / `<script>`, dans l'ordre de l'architecture (§3).
2. Étant donné les fichiers `style.css` et `js/base.js`, `js/liaison.js`, `js/duel.js`, `js/grille.js`, `js/plateau.js`, `js/choix-categories.js`, `js/accueil.js`, `js/regie.js`, `js/main.js`, quand on concatène leur contenu dans l'ordre de chargement, alors on retrouve le code d'origine, aux seuls commentaires d'en-tête de fichier près (vérifié par un script de comparaison).
3. Étant donné `tests/fumee.js` et `tests/regie.js`, quand on les lance après le découpage, alors ils passent comme avant.
4. Étant donné `editeur.html` et `credits.html`, quand on y va depuis l'accueil puis qu'on revient, alors tout fonctionne comme avant (code conservé, retour sans redemander le lancement).
5. Aucun renommage, aucune correction, aucune nouvelle fonctionnalité dans la PR.

### Contexte dev
- `index.html` : 1 414 lignes ; `<style>` lignes 8 à 193 ; script principal lignes 362 à 1412. Sections repérées : liaison (≈ 436), connexion de l'arbitre (≈ 638), accueil (≈ 703), grille (≈ 823), choix des catégories (≈ 850), plateau SVG (≈ 998), retourner sur le sol (≈ 1165), régie (≈ 1293). Le début (≈ 362 à 635) contient constantes, `normItem`, duel : à répartir entre `base.js` et `duel.js`.
- Les scripts classiques partagent l'espace global, mais **les `const` et `let` de niveau supérieur aussi** (portée globale du script) : pas besoin de `window.`. Attention en revanche à l'ordre : une `const` utilisée au chargement doit être déclarée dans un fichier chargé avant.
- `qrcode.js`, `intro.js`, `sons.js`, `categories.js`, `photos.js`, `perso.js` restent chargés aux mêmes positions relatives.
- Piège : `hidden` et attributs `onclick` éventuels dans le HTML qui appellent des fonctions globales : ils marchent toujours, tant que les fonctions sont chargées avant l'interaction.

### Notes de réalisation (Dev, 27 novembre 2026)
- **Ordre de chargement = ordre du code d'origine**, pas celui de la liste de l'architecture : pour que la concaténation redonne le code d'origine (critère 2) et que le diff se lise comme un déplacement, chaque fichier est un morceau contigu de l'ancien script. Ordre retenu : `base` → `liaison` → `duel` → `accueil` → `grille` → `choix-categories` → `plateau` → `regie` → `main`. `docs/architecture.md` §3 est mis à jour en conséquence.
- **Contenu réel des fichiers** (différent de l'architecture sur trois points, pour la même raison) :
  - `js/accueil.js` contient aussi la gestion de la liaison côté écran du jeu (`onmsg`, `getLink`, `resetLink`) et la section « Connexion de l'arbitre » (`#pair`), placées juste avant l'accueil dans le code ;
  - `js/grille.js` ne garde que l'état `G`, la case d'or, le voisinage et les noms des joueurs (27 lignes) ; `startGrid` est en fin de `js/choix-categories.js` ;
  - `js/plateau.js` contient aussi « Retourner sur le sol », `gridRender`, `startGridDuel`, `gridAfterDuel` et les boutons du duel (`f2`, `pass`, `go`, `again`), qui suivaient le plateau dans le code.
  Si on veut ranger ces fonctions ailleurs, ce sera une story à part (déplacement de fonctions entre fichiers), pour garder celle-ci relisible.
- **Dépendances au chargement** : vérifiées par une analyse statique ponctuelle (acorn, non versionnée) : aucun code exécuté au chargement n'appelle une fonction ni n'utilise une variable déclarée dans un fichier chargé plus tard (les déclarations de fonction ne remontent qu'à l'intérieur de leur propre fichier). Seuls des gestionnaires d'évènements (clic, touche, envoi de formulaire, redimensionnement) y font référence, et ils ne servent qu'après le chargement complet.
- **Vérifications** : script de comparaison ponctuel (non versionné) : JS (1 049 lignes) et CSS (184 lignes) identiques au code d'origine, en-têtes mis à part ; reste d'`index.html` identique. `tests/fumee.js` et `tests/regie.js` passent. QA en plus : même parcours sur l'ancien et le nouveau `index.html` (hasard et horloge fixés ; accueil, lancement, régie 390×844, configuration, grille 4×4, adversaire, duel, éditeur et retour, crédits et retour), captures comparées pixel par pixel : identiques, sauf le QR code (adresse de test différente) et le titre animé « Partie en préparation » (animation CSS) ; aucune erreur JavaScript ; retour de l'éditeur et des crédits sans nouveau choix du lancement, même code.
- **Préchargement des photos** : confirmé absent (`new Image()` seulement à l'affichage, dans `paintCard`) ; story 2.3 maintenue.
