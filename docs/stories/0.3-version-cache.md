## Story 0.3 — Version des fichiers (cache de la TV)
En tant que joueur sur la TV, je veux que la TV charge la dernière version du jeu après une mise à jour afin de ne pas jouer avec un mélange d'anciens et de nouveaux fichiers.

### Critères d'acceptation
1. Étant donné une constante `VERSION` (par exemple `"2026-11-24a"`) définie une seule fois, quand `index.html` se charge, alors chaque fichier CSS et JS du jeu est demandé avec `?v=<VERSION>`.
2. Étant donné `editeur.html` et `credits.html`, quand ils chargent des fichiers JS partagés (`categories.js`, `perso.js`, `photos.js`…), alors ils utilisent la même version.
3. Étant donné le pied de l'accueil, quand on l'affiche, alors la version apparaît en petit (utile pour vérifier ce que la TV a chargé).
4. Les tests de 0.1 passent.
5. `CLAUDE.md` indique de monter `VERSION` dans chaque PR qui touche du code.

### Tâches techniques
- [x] Choisir la mise en œuvre la plus simple compatible avec des scripts classiques : un petit script en ligne en tête de page qui écrit les balises avec `document.write`, ou des `?v=` en dur remplacés par un script `tools/version.py`. Noter le choix dans la story.
- [x] Appliquer aux trois pages HTML.
- [x] Afficher la version sur l'accueil.
- [x] Mettre à jour `CLAUDE.md` et sa copie.

### Contexte dev
- Les images de `assets/` ne sont pas concernées (leurs noms changent quand le contenu change).
- Piège : `document.write` bloque le rendu et est déconseillé ; une version en dur maintenue par un script est plus sûre. Décider en Dev, en restant sans build pour le jeu.

### Notes de réalisation (Dev, 27 novembre 2026)
- **Choix : version en dur, maintenue par un script** (`tools/version.py`), pas de `document.write`. La version est **définie une seule fois** dans `<meta name="slc-version">` d'`index.html` ; le script la recopie en `?v=<version>` sur chaque fichier CSS et JS local des trois pages, et dans le pied de l'accueil. Aucun code exécuté au chargement, rien à construire : la page publiée est celle du dépôt.
  - `python3 tools/version.py` : nouvelle version (date du jour + lettre : `2026-11-27a`, puis `b`…) ;
  - `python3 tools/version.py 2026-12-01a` : version donnée ;
  - `python3 tools/version.py --verifier` : contrôle seul (code de sortie 1 si une page n'est pas à jour).
- **`intro.css`** est chargé par `intro.js` : il reprend la version de l'adresse d'`intro.js` (une ligne changée dans `intro.js`).
- **Affichage** : « Version 2026-11-27a » en petit dans le coin bas droit de l'accueil (toujours visible sur la TV, sans défiler) ; sous les liens, centré, sur un écran étroit (pour ne pas recouvrir « Ouvrir la régie »).
- **Test** : `tests/fumee.js` vérifie en plus que les 17 fichiers CSS et JS demandés portent tous `?v=<version>` (`intro.css` compris) et que le pied affiche la même version. `editeur.html` (`perso.js`) et `credits.html` (`photos.js`) vérifiés à part : même version, aucune erreur.
- Version de cette PR : `2026-11-27a`.
