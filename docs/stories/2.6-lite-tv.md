## Story 2.6 — Mode allégé sur les TV récentes
En tant que famille qui joue sur une TV connectée, je veux que la vague de capture reste dans les cases capturées, afin que le plateau reste lisible.

**Pourquoi** : test réel du 27-28 novembre 2026 sur la TV de Ced (Samsung TQ55S95C). La vague débordait encore. Le cadre `?debug=1` affichait : version `2026-11-27r`, Chromium 120, « color-mix : oui · mode allégé : non », user agent `SMART-TV; Linux; Tizen 8.0 … SamsungBrowser/7.0 Chrome/120`. L'architecture supposait un Chromium M94 (Tizen 7.0) sans `color-mix()` ; la TV a été mise à jour, gère `color-mix()`, mais ignore toujours le `clip-path` qui découpe la vague. La détection du mode allégé par `color-mix()` ne suffit donc pas.

Parcours rapide BMAD (correctif) : mini-spec, Dev, QA.

### Critères d'acceptation
1. Sur une TV connectée (user agent contenant `SMART-TV`, `SmartTV`, `Tizen`, `Web0S`, `webOS`, `HbbTV`, `NetCast` ou `BRAVIA`), le mode allégé est actif même si `color-mix()` est pris en charge.
2. `?debug=1` affiche « mode allégé : oui (TV détectée) » sur une TV, et « (forcé par ?lite=1) » quand c'est le paramètre.
3. `?lite=0` empêche le mode allégé (dépannage, pour comparer sur la TV).
4. Ordinateur et téléphone récents : inchangés (pas de mode allégé).
5. `tests/lite.js` vérifie 1 à 4 avec le user agent exact de la TV de Ced ; il échoue sans le correctif. Les autres tests passent.

### Notes de réalisation (Dev, 28 novembre 2026)
- Détection par le user agent plutôt que par une fonction CSS : le défaut (`clip-path` ignoré sur le SVG) ne se teste pas par `CSS.supports`. Liste large de marqueurs de TV (Samsung, LG, Sony, HbbTV) : le mode allégé ne coûte rien de visible sur une TV.
- `tests/lite.js` remplace `navigator.userAgent` par celui de la photo de Ced ; il échoue si on retire `SLC_TV` de `LITE`.
- Version `2026-11-28a`.
